# Working skeleton - notes module and homepage

Approved design for a runnable Kraken v2-shaped app: Next.js App Router, tRPC, Drizzle, Postgres.
One public module (`note`) and `/` listing its rows.
No auth, workspaces, design system, pg-boss, or per-branch databases.

## Goal

After `bun install`, `bun run db:up`, `bun run db:migrate`, `bun run db:seed`, and `bun dev`, opening `/` shows three seeded notes as cards.
The homepage reads them through `trpc.note.listNotes`.
A visitor is not asked to log in.

## Out of scope

- Login, sessions, SSO, permissions, workspaces
- Mutations, create/edit/delete UI
- Kraken design system, dark theme, navigation chrome
- pg-boss, Sentry, module-boundary generator, per-branch DB scripts
- Anything under `.ai/`

## Stack

- Next.js 16 App Router, Turbopack, React 19
- TypeScript strict, named exports only, `type` not `interface`
- tRPC v11 + superjson + TanStack Query
- Drizzle ORM + `postgres` driver
- PostgreSQL 17 in Docker Compose (local only)
- bun, Biome, Tailwind v4, Vitest
- Package name: `projekt`

## Data

Table `note__note_`:

| Column | Type | Rules |
| --- | --- | --- |
| `id` | uuid | PK, default `uuid_generate_v7()` from Postgres. Never set in app code. |
| `title_` | text | not null |
| `body_` | text | not null |
| `created_at_` | timestamptz | not null, `defaultNow()` |

Migration `0000` enables `uuid_generate_v7()`.
Migration `0001` creates `note__note_`.
Generated SQL is immutable once written.

`note.seed.ts` is idempotent: if the table has any row, it inserts nothing.
Otherwise it inserts exactly these three rows, in this order:

1. title `Welcome` - body `This skeleton lists notes from Postgres through tRPC.`
2. title `Vertical slice` - body `The note module owns its schema, router, and listNotes query.`
3. title `Homepage` - body `The App Router page prefetches listNotes and renders one card per row.`

## Endpoint

`note.listNotes` is a `publicProcedure` query.
Meta: `{ operation: 'note.listNotes', procedureKind: 'query' }`.
Input: `z.object({})` in `input.dto.ts`.
Output: `{ notes: Array<{ id: string, title: string, body: string, createdAt: Date }> }` in `output.dto.ts`.
Order: `created_at_` ascending.
Empty table returns `{ notes: [] }` - not an error.
A database failure surfaces as tRPC `INTERNAL_SERVER_ERROR`.
No `internal-functions/` (single consumer).
No `permissions.ts`.
Router key: `listNotes`.
Every future `db.update` / `db.delete` must have `.where()`.

## Homepage

`/` is a Server Component.
It prefetches `trpc.note.listNotes.queryOptions({})` through the RSC caller, then hydrates a client list the same way Kraken does (`prefetch` + `useQuery`).
Page heading: `Notes`.
Each note is a card: title, then body.
User-facing copy is Polish except the heading `Notes` and the seeded English note text.
Empty list copy: `Brak notatek`.
`loading.tsx` renders three grey blocks in the same card layout - never a spinner, never the word "Loading".
`error.tsx` copy: `Nie udało się wczytać notatek.`
No stack trace on that screen.
No nav, login, or theme toggle.
Files: kebab-case, one component per file, named exports.
Colors from CSS variables in `globals.css`, not Tailwind palette defaults like `bg-blue-500`.
Layout spacing via parent `gap`, not child margins.

## Local run

`.env.example` documents `DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/projekt`.
Docker Compose service `postgres` (image `postgres:17-alpine`), db name `projekt`, user/password `postgres`, port `5432` overridable via `POSTGRES_PORT`.
Scripts: `dev`, `build`, `lint`, `format`, `typecheck`, `db:up`, `db:down`, `db:migrate`, `db:seed`, `test`, `test:integration`.
`dev` uses the `.env` `DATABASE_URL` as-is (no branch suffix).
Agents starting a server pick a port in 3200-3899, never 3000.

## Tests

Vitest.
Never mock the database.

Unit (`bun run test`): `ListNotesOutputDTOZ` rejects a payload whose `notes[0]` omits `title`.

Integration (`bun run test:integration`) against a real database named `projekt_test` on the same Docker Postgres, created by the suite if missing:

1. After seed, `listNotes` returns three notes whose titles are `Welcome`, `Vertical slice`, `Homepage` in that order, each with non-empty `id`, `body`, and `createdAt`.
2. After truncating `note__note_`, `listNotes` returns `{ notes: [] }`.
